# Security and privacy boundaries

## OpenRouter credential

The only external AI credential is an OpenRouter API key. `OpenRouterSecretVault` stores it as a non-synchronizable generic-password item in the macOS login Keychain, with a dedicated service/account identifier. This does not require the data-protection Keychain entitlement in local or Developer ID builds. The vault can still read and remove an older data-protection item when the process has access to it. The app does not serialize the key into UserDefaults, project files, databases, JSON, plist, logs, telemetry, source code, or subprocess arguments. Authorization headers and response bodies are never logged. Standard app errors do not contain the key; full operating-system memory dumps may still contain in-memory request data. A missing or inaccessible key fails closed with a user-facing error.

`LiveOpenRouterGateway` obtains the key from the vault at request time and injects it into the HTTPS header in process memory. It uses an ephemeral URL session, fixed OpenRouter HTTPS endpoints, refuses redirects, bounds response bytes, and maps HTTP/network failures to sanitized errors without returning server text. The Settings Test action uses only the key-inspection endpoint; it does not run a model. Model IDs and task capabilities are fetched/configured through the gateway, not frozen into core models. Tests inject a fake vault and a mocked gateway; tests make no paid calls.

## Untrusted boundaries

| Boundary | Required control |
| --- | --- |
| Local/remote source → `SourceIngestor` | User authorization, supported format, size/duration limits, safe file access; no DRM, access-control, or private-media bypass |
| URL → remote acquisition | HTTPS only; block local/private addresses, redirects, URL credentials, and oversized downloads; keep provider-specific handling behind `SourceIngestor` |
| Media bytes → decoder | Treat as malformed; isolate failures and never modify source |
| AI JSON → typed models | Decode, validate ranges/scores/IDs, then check against asset/proposal/project context |
| Typed edit spec → renderer | Resolve asset IDs internally; validate version, times, output size, permissions and destination; do not execute AI-supplied strings |
| Project manifest → runtime | Version check, bounded decode, validate IDs/references; reject corrupt or unsupported data without destroying originals |

Only transcript excerpts, necessary metadata, and selected keyframes may leave the device. Entire original videos never go to AI. Vision runs as fallback for difficult shots. User-owned or authorized YouTube media only; no extraction workaround is authorized by this architecture.

**Direct video URLs are disabled in production.** `SourceImportPolicy.directURLImportEnabled` is `false`; the public `SourceIngestor` constructor rejects a direct URL before DNS resolution, a cache lookup, or a network task. New-project UI hides this source type, and older direct-URL projects explain why reattachment is unavailable. A debug-only internal constructor lets tests exercise the dormant downloader. The old downloader's initial DNS check cannot bind `URLSession` to the checked address, so it must not be enabled in an external build. Re-enable only after the actual connected address is validated or pinned across every connection and redirect, with DNS-change tests. No redirect is currently followed by the dormant downloader.

The dormant direct downloader accepts HTTPS without URL credentials, refuses redirects, omits cookies, stops at 2 GB, and validates completed media with AVFoundation under `forbidAll` external-media references. These controls do not fix DNS rebinding. YouTube accepts a canonical video ID and runs a trusted local `yt-dlp` executable with fixed arguments, isolated HOME, disabled configuration/plugins/cookies, no shell, and no private-media workarounds. Download output is kept in a private temporary directory and removed on failure or cancellation; abandoned session directories older than one day are swept before the next remote import. The third-party downloader and its redirect behavior remain a distinct supply-chain/network boundary that requires distribution testing.

## Distribution boundary

The local Release bundle has passed Developer ID signing with hardened runtime and a secure timestamp. It has no App Sandbox entitlement. It has not been notarized or installed on a clean Mac. The app does not bundle `yt-dlp`: the user must install it separately, and FFmpeg is needed to merge separate high-resolution streams. A trial of the official one-file `yt-dlp_macos` release under ClipHelm's Developer ID hardened-runtime signature could not load its embedded Python library because library validation rejected the different signing team. Do not ship that binary by disabling library validation; a bundled helper needs a separately verified signing and notarization path. The Keychain tests establish application behavior, not a guarantee about full operating-system memory dumps. Do not collect or share full process dumps without credential redaction. External distribution remains blocked by the release checklist.

Phase 4 media jobs accept local file URLs from `SourceIngestor` and use security-scoped access while reading. AVFoundation assets forbid external media references. The optional FFmpeg fallback resolves only fixed local executable paths, passes built arguments directly to `Process`, restricts input protocols to local files/pipes, discards subprocess stderr, and never receives an AI response. Media derivatives use private directories and file permissions, are disposable, and are removed after failed or canceled jobs. Original source bytes are never an output target.

Phase 5 on-device transcription requests macOS Speech permission and sets `requiresOnDeviceRecognition`; it fails when that mode is unavailable. OpenRouter transcription is an explicit paid action, uses the existing Keychain credential and fixed HTTPS gateway endpoint, and sends at most one short, extracted audio chunk per request. Responses are bounded and parsed into validated word times; server error bodies are discarded. Temporary audio is deleted after each chunk or cancellation. Transcripts are local project data, not credentials, and are saved in private project manifests. A matching local source must be selected again after relaunch for playback; the source URL itself is not persisted.

Phase 6 local analysis reads only the user-selected media file. AVFoundation forbids external media references; Vision runs on decoded local frames. `ClipHelmAnalysis` has no OpenRouter or network dependency, and analysis starts only from a workspace action. The cache stores bounded numerical evidence and tentative labels, with no raw frame, audio, source URL, or credential. Cache reads enforce size, version, source fingerprint, asset identity, and timeline bounds before use. Cache writes are atomic with private permissions.

Phase 7 moment discovery uses the same Keychain credential and fixed OpenRouter HTTPS gateway. The user selects a structured text model and starts the paid action in the workspace. Each request is capped and contains one candidate's sampled transcript words and local metadata; no original video, raw frame, path, or full transcript is sent. The gateway refuses redirects and bounds response bytes. `ClipProposal` JSON is treated as untrusted: unknown fields, altered IDs/times, invalid dimensions, and out-of-source ranges are rejected before local ranking. Its title and rationale are display text only, never renderer input. Silent-video discovery makes no AI request.

Phase 10 AI Vision is opt-in and operates only on uncertain scenes. The helper sends at most two 512-pixel JPEG frames per scene and examines no more than three scenes per invocation. Frames are written to a private temporary directory and removed after use or failure. The gateway accepts only bounded JPEG bytes, sends them to its fixed HTTPS chat endpoint, and requests a strict classification schema. The response must contain exactly a known content kind and finite confidence in 0...1; extra fields are rejected. No model coordinate, URL, path, or command reaches `ClipHelmEditSpec`. The model must advertise vision and structured-output capabilities, although catalog metadata cannot guarantee a provider will honor the format. See [OpenRouter image input](https://openrouter.ai/docs/guides/overview/multimodal/image-understanding) and [structured output](https://openrouter.ai/docs/guides/features/structured-outputs) documentation.

Phase 11 screen subtype detection uses macOS Vision locally on a bounded set of reduced thumbnails. Temporary thumbnails are private and removed after the operation. AI Vision runs only when enabled, a structured vision model is selected, and local evidence leaves a screen window uncertain; it sends two 512-pixel JPEGs from at most three such windows. The gateway uses the same Keychain credential and fixed HTTPS endpoint. Model output is accepted only as a known subtype plus finite numeric confidence, with no extra fields; layout names, crop coordinates, URLs, paths, and commands from a response are rejected. The validated subtype is evidence for local `SmartLayoutEngine` decisions, not an edit-spec instruction.

## Verification status

Core decoding rejects malformed timing, geometry, scores, unsupported spec versions, and invalid proposals. Gateway tests check the fixed endpoint, authorization placement, sanitized errors, catalog capability selection, and rejected malformed key input. The Keychain save/replace/remove test uses a unique test service and runs without API spend.
